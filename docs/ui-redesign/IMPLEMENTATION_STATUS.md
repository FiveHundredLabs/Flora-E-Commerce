## Access, integration and status keys

- Public/customer URLs: publicly reachable demo, no customer session. Supplier/admin URLs: role-specific shells, publicly reachable local demos with fixture capability checks; **no authenticated role enforcement**.
- D = discovery `query.ts` / `api/mock.ts`; C = commerce equivalents and `cart.tsx`; S = supplier equivalents; A = admin equivalents. All use local fixtures, no HTTP endpoint. W = `discovery/wishlist.ts`, localStorage only. Hooks are named per row. No row has a live backend integration.
- Current status for every routed feature: implemented legacy UI, awaiting redesign. Supplier/admin command success changes sample state only. Missing live contracts are listed in the audit; async states below are source inventory, not assertions that browser accessibility passed.
- Shared dependencies for every row: `Shell`, `RouteAccessibility`, `ErrorBoundary`, tokens/global styles. UI primitives and feature-specific components are inventoried in the audit.
- Tests column identifies existing regression files/areas unless explicitly marked needed. Actual execution results live in the verification report. New component names are proposals; retain public APIs where possible.
